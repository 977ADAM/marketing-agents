# Переезд хранилища с SQLite на MariaDB — Implementation Plan

**Дата:** 2026-10-05
**Область:** `backend`, `docker-compose.yml`, `Makefile`, `README.md`
**Принцип:** жёсткая замена хранилища (SQLite выпилен целиком), поведение сервиса и
API не меняется; данные не переносятся — база поднимается с нуля.

## Задача

Хранилище было файлом SQLite внутри контейнера бэкенда. Нужна MariaDB — обычный
серверный процесс, к которому могут подключаться несколько клиентов. Отдельное
требование — **размер образов**: SQLite не стоил ни байта, MariaDB стоит сотни
мегабайт, поэтому образ выбирался осознанно.

## Размеры, из которых выбирали

Сжатый размер (то, что реально тянется при `docker pull`) — Docker Hub API,
«на диске» — замер `docker images` на этой машине:

| Образ | pull (сжатый) | на диске |
|---|---|---|
| `mariadb:11.4` (official, Ubuntu noble) | **100.7 МБ** | **490 МБ** |
| `mariadb:10.11-jammy` (official LTS) | 99.3 МБ | — |
| `mariadb:11.4-ubi9` | 155 МБ | — |
| `yobasystems/alpine-mariadb:11.4` (community) | 81.8 МБ | — |
| свой `alpine:3.22` + `apk add mariadb mariadb-client` | ~80 МБ (оценка) | 316 МБ |

Alpine-варианта у официального образа нет: Docker Hub по `name=alpine` отдаёт
`count=0`, есть только noble / jammy / ubi9
([теги library/mariadb](https://hub.docker.com/_/mariadb/tags)). Свой alpine-образ
собран и замерен: 316 МБ против 490 МБ, то есть −174 МБ на диске ценой
собственного entrypoint, инициализации datadir и healthcheck.

**Решение: официальный `mariadb:11.4`.** Экономия диска не стоит поддержки
собственного образа БД, а обновления безопасности и готовый `healthcheck.sh`
нужны на сервере, где диск не узкое место. Community alpine-образ от третьей
стороны не берём по той же причине.

Вторая половина счёта — наши образы: драйвер MariaDB дешевле SQLite-драйвера.

| Состав статического бинаря | Размер |
|---|---|
| `database/sql` | 2.72 МБ |
| + `go-sql-driver/mysql` | 4.43 МБ (+1.71 МБ) |
| + `modernc.org/sqlite` (было) | 9.26 МБ (+6.54 МБ) |

Бинарь сервиса: **17 МБ → 11.7 МБ** (−5.3 МБ), образ бэкенда — 22.5 МБ (distroless
static).

## Решения по развилкам

1. **Хранилище:** MariaDB 11.4, официальный образ, том `mariadb`, публикация только
   на `127.0.0.1:3306` (локальный API без Docker ходит в контейнер с хоста).
2. **Драйвер:** `github.com/go-sql-driver/mysql` — чистый Go, официально
   поддерживает MariaDB 10.11+ ([README драйвера](https://github.com/go-sql-driver/mysql)).
3. **Миграции:** остаётся dbmate (`mysql://`-адреса — та же схема, что у MySQL):
   он сам создаёт базу, умеет `--wait` до готовности сервера и пишет версии в
   `schema_migrations (version)`. Приложение миграции не применяет — как и раньше,
   сервер только проверяет готовность схемы.
4. **Тесты:** нужен живой сервер. Адрес — `TEST_DATABASE_URL`, каждому тесту
   `internal/testdb` заводит отдельную временную базу и удаляет её после (та же
   изоляция, что давал файл в `t.TempDir()`). Учёт для тестов — root: базы создаёт
   сам тест. `make test-backend` поднимает контейнер и подставляет адрес из
   `backend/.env`; без Docker тесты с БД пропускаются с понятным сообщением.
5. **Данные:** не переносятся (база была пустой, схема создаётся с нуля).

## Что изменилось в коде

### Схема (`backend/migrations`)

- `TEXT` → `VARCHAR(36)` для id и `VARCHAR` для коротких полей: в MariaDB `TEXT`
  нельзя индексировать без префикса, а у нас `id` — первичный ключ, `run_id` — в
  индексе;
- `MEDIUMTEXT` (16 МБ) для стратегии, прогресса, тел статей, payload трассы и
  ошибок: `TEXT` — это 64 КБ, статьи и стратегия со всеми кандидатами в него не
  гарантированно влезают;
- `REAL` → `DOUBLE`, `strftime(...)` → `CURRENT_TIMESTAMP(3)` (плюс
  `--default-time-zone=+00:00` у сервера и `time_zone='+00:00'` в DSN, чтобы
  значение по умолчанию и время из Go означали одно и то же);
- `INSERT ... ON CONFLICT DO NOTHING` → `INSERT IGNORE`, `CREATE INDEX IF NOT
  EXISTS` → индексы внутри `CREATE TABLE` (в MariaDB индексы уходят вместе с
  таблицей), `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`;
- `seq BIGINT AUTO_INCREMENT` в `campaigns` и `reviews` — замена `rowid`: без
  тайбрейкера «новые сверху» при одинаковом `created_at` (точность —
  миллисекунды) недетерминированы;
- `position INT` в `deliverables` — порядок статей в медиаплане (раньше его
  держал `rowid`).

### Адаптер (`internal/sqlite` → `internal/mariadb`)

Пакет переименован по зависимости и разложен так же по сущностям
(`mariadb.go`, `campaign.go`, `review.go`, `trace.go`, `schema.go`).

- `mariadb.DSN` переводит `DATABASE_URL` (`mysql://user:pass@host:3306/db`) в DSN
  драйвера и добавляет обязательные настройки: `parseTime`, `loc=UTC`,
  `time_zone='+00:00'`, `timeTruncate=1ms` (у драйвера это неэкспортируемое поле,
  поэтому задаётся строкой DSN), `collation=utf8mb4_unicode_ci`, таймауты;
  параметры из адреса понимаются как настройки драйвера, неизвестные — как
  системные переменные соединения;
- пул соединений вместо pragma SQLite: `MaxOpenConns` 8, `ConnMaxLifetime` 3
  минуты; `WAL`, `busy_timeout`, `_txlock=immediate` больше не нужны — конкурентные
  записи прогресса разводит InnoDB, внешние ключи работают всегда;
- `CheckSchema` читает `information_schema` вместо `sqlite_master` и
  `PRAGMA table_info`;
- `nowExpr` → `UTC_TIMESTAMP(3)`; время пишется как `time.Time`, а не строкой;
- `ORDER BY ... rowid` → `ORDER BY created_at DESC, seq DESC` (списки) и
  `ORDER BY position` (статьи);
- `TARGET`-хелпер печатает адрес БД без пароля — для логов.

### Конфигурация и компоуз

- `SQLITE_PATH` → `DATABASE_URL`; адрес по умолчанию собирается из `MARIADB_*`
  (`HOST`, `PORT`, `DATABASE`, `USER`, `PASSWORD`) — те же переменные понимает
  официальный образ MariaDB, поэтому в compose и контейнер БД, и приложение берут
  их из одного `backend/.env`, а приложению переопределяется только
  `MARIADB_HOST=mariadb`. Пароли в URL экранируются, в сообщениях об ошибках не
  показываются; адрес вида `sqlite:`, путь к файлу или `postgres://` — ошибка
  старта с подсказкой;
- сервис `mariadb` с healthcheck `healthcheck.sh --connect --innodb_initialized`;
  `migrate` собирает `DATABASE_URL` внутри контейнера из `MARIADB_*` (compose не
  умеет интерполировать переменные из `env_file`), откат — `DBMATE_CMD=rollback`;
- `Makefile`: `db-up`/`db-down`, `TEST_DATABASE_URL` из `backend/.env`
  (`-include`), тесты поднимают контейнер сами;
- роль `MARIADB_ROOT_PASSWORD`: только сервис `mariadb` и тесты.

## Приёмка

- `go build ./...`, `go vet ./...`, `gofmt -l` — чисто; `go test ./...` зелёный на
  живой MariaDB (включая `tests/e2e`, который проходит через раннер, трассу и
  стор);
- фронт не тронут: `npm run check` — 0 замечаний, `npm test` — 34 теста;
- стек `docker compose up -d` поднимается, `/healthz` через фронт отвечает `ok`,
  `/api/campaigns` и `/api/reviews` отдают `[]` из MariaDB, схема на месте;
- размеры: бинарь 11.7 МБ (−5.3 МБ), образ бэкенда 22.5 МБ, `mariadb:11.4` —
  490 МБ на диске (101 МБ сжатым). Фронт — 237 МБ, сервис миграций (dbmate,
  one-shot) — 127 МБ на диске.

## Что осталось / риски

- **Экономия образа БД** возможна только своим alpine-образом (~316 МБ) или
  внешним сервером MariaDB — оба варианта вне этой задачи;
- **Переноса данных из SQLite нет** — при необходимости это отдельный шаг
  (`.dump` → преобразование типов → вставка);
- **`-include backend/.env` в Makefile**: значения со спецсимволами (`#`, `$`)
  в этом формате могут сломаться; пароли, которые генерирует `openssl rand -hex`,
  безопасны. Если появится пароль со спецсимволами — задавать `TEST_DATABASE_URL`
  вручную;
- **Моков БД нет:** тесты ходят в настоящую MariaDB — это цена реалистичности
  (диалект, транзакции, внешние ключи проверяются по-настоящему).
