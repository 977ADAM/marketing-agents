# Прозрачность агентов в трассе прогона

Дата: 2026-10-06. Статус: согласовано пользователем (решения по двум развилкам).

## Проблема

Трасса технически пишет вызовы модели, решения и итог, но пользователь не видит,
что именно делали агенты:

1. `TRACE_MODE=summary` по умолчанию — тел промптов и ответов в БД нет вовсе,
   поэтому по умолчанию трасса не показывает ничего, кроме метрик.
2. Даже в режиме `full` модель отдаёт `reasoning_content` (chain-of-thought), а
   клиент читает только `Message.Content`: размышления агента выбрасываются.
   Проверено живым вызовом 2026-10-06 на `deepseek-v4-pro`: поле есть и в обычном
   ответе, и с `response_format: json_object`; счётчик —
   `usage.completion_tokens_details.reasoning_tokens`.
3. Тело события обрезается целиком в одну строку по `TRACE_MAX_PAYLOAD_BYTES`
   (32 КиБ): длинный системный промпт вытесняет и запрос, и ответ, и размышления,
   а UI показывает `{data,truncated}` с `data`-строкой.
4. Вьюер рисует payload как сырой JSON в `<pre>`: промпт и ответ — экранированные
   строки внутри JSON, читать их невозможно.
5. `trace.KindPhase` объявлен и подписан в UI («Этап»), но не эмитится нигде:
   в ленте нет смены этапов, только отдельные вызовы и решения.

## Решения

1. **`TRACE_MODE=full` по умолчанию** — в `config.Load`, в `trace.ParseMode` (пустое
   значение) и в `backend/.env.example`. В `full` в БД попадают брифы, промпты и
   черновики статей открытым текстом, поэтому сервер при старте пишет
   предупреждение, если `full` включён, а `BASIC_AUTH_USER` не задан (доступ
   открыт). README фиксирует это как осознанный режим разработки.
2. **Размышления модели — часть трассы.** `corellm.Usage` получает `Reasoning`,
   `ReasoningTokens` и `FinishReason`; адаптер DeepSeek заполняет их из
   `Message.ReasoningContent`, `Usage.CompletionTokensDetails.ReasoningTokens` и
   `Choices[0].FinishReason`. Трасса пишет размышления в теле события, а счётчик
   размышлений — в `summary` (виден и в `summary`-режиме, без тел).
3. **Длинные тексты обрезаются по отдельности.** `trace.TruncateText` и
   `trace.TruncatedMark` переезжают в domain (в recorder.go лежит мёртвый
   `truncate`); декоратор LLM обрезает каждое поле тела (`system`, `user`,
   `reasoning`, `response`) до `trace.MaxBodyBytes` (32 КиБ) и перечисляет
   обрезанные поля в `truncated_fields`. Общая обрезка конверта рекордером
   остаётся жёстким заслоном, но при дефолтном бюджете не срабатывает.
4. **Дефолт `TRACE_MAX_PAYLOAD_BYTES` — 256 КиБ** (4 × 32 КиБ тел плюс метаданные),
   чтобы событие помещалось целиком. Колонка `payload` — `MEDIUMTEXT` (16 МиБ),
   так что запас есть; ретенция событий не меняется.
5. **UI показывает размышления, а не JSON.** Логика нормализации payload живёт в
   `frontend/src/lib/trace-payload.ts` (юнит-тесты), панель трассы рисует секции
   «Размышления», «Системный промпт», «Запрос», «Ответ» с пометкой обрезки;
   для остальных видов остаётся pretty-JSON.
6. **Смена этапов пишется в трассу** (`KindPhase`): `pending`, `researching`,
   `strategizing`, `producing`, `done`/`failed` — по одному событию на переход,
   без payload. Это делает ленту читаемой как последовательность действий.

## Границы

- Модель не меняется: `reasoning_content` приходит и сейчас, трасса лишь перестаёт
  его выбрасывать. Расход не растёт — `completion_tokens` уже включает
  `reasoning_tokens`, тарификация не меняется.
- Не делаем: стриминг размышлений в реальном времени, отдельные эндпоинты под
  размышления, реплей-фикстуры, экспорт трассы, агрегаты по стоимости (это
  отдельные пункты Фазы 3 спеки трассы).
- Ключи API не логируются; размышления и промпты попадают только в БД трассы.

## Проверки

- `internal/adapters/llm/deepseek`: httptest-ответ с `reasoning_content`,
  `reasoning_tokens` и `finish_reason` → поля `Usage` заполнены.
- `internal/adapters/tracing`: событие LLM содержит размышления, модель,
  `finish_reason`; длинное поле обрезано и помечено; короткое — нет.
- `internal/core/config`: пустой `TRACE_MODE` даёт `full`; явный `summary` не ломается.
- `frontend`: vitest на `trace-payload.ts` (конверт `{data,truncated}`, разбор
  размышлений и ответа, JSON-ответ как объект, строка как текст).
- `make verify` (Go + MariaDB, frontend test/check/build).
